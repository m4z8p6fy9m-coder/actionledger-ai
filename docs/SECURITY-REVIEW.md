# Security and provider-contract review

Status: **experimental; internal review checklist, not an independent audit or production certification**. This document records boundaries and unresolved work, not assurance that every control has been adversarially tested.

| Boundary / threat                  | Existing control or behavior                                                                | Residual risk and work before production                                                                                                                                                                                                                                            |
| ---------------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Agent and operator credentials     | Headless API uses distinct scoped tokens; approval requires the operator credential.        | Anyone able to read operator files or act as operator can approve. Reviewer names are not authenticated identities. Require managed identity, RBAC, secret management and independent authorization review.                                                                         |
| Local HTTP and network             | Local services use loopback and validate host/origin; runtime rejects browser origins.      | No built-in production TLS, enterprise authentication or complete runtime rate limiting. Design and verify a trusted ingress and deployment controls.                                                                                                                               |
| Mutable requests and trusted hosts | Host-owned intent and MCP payload checks reject a mismatch; causal manifests can be signed. | Legacy non-causal intents may be unsigned; a compromised host, connector or database is outside these checks. Protect signing keys and assess manifest provenance and rotation.                                                                                                     |
| Provider side effects              | Stable keys and conservative UNKNOWN handling reduce unsafe replay within documented flows. | Local fencing cannot stop an already dispatched request. Direct provider access bypasses ActionLedger. Provider-side idempotency and retention must be verified for each operation and account.                                                                                     |
| Stripe events and recovery         | Signature verification precedes webhook processing; recovery checks provider evidence.      | Current tests use a local mock, not live Stripe. Search can be incomplete or delayed; missing evidence remains UNKNOWN. Independently verify current Stripe API semantics, webhook replay/rotation, permissions and key retention in a controlled test account before any real use. |
| Tenants and multi-agent locks      | Optional guard uses a host-bound prompt-hash/asset pair in a shared database.               | No complete tenant isolation or resource-wide conflict detection; differing prompt hashes and bypass paths can escape a collision. Use separate stores or qualified IDs only as limited scoping, not as authorization.                                                              |
| Storage, logs and recovery         | Audit and state are persistent; uncertain outcomes are retained.                            | A database administrator can alter records; logs and backups are not tamper-proof. Evaluate integrity, access, encryption, retention, backup/restore and incident handling. Never force replay merely because a lease expired.                                                      |
| Availability and operations        | Leases and retry limits bound some operations; UNKNOWN is retained.                         | Review clock skew, database outages, resource exhaustion, recovery backlog and manual escalation. Test failover and restore under realistic conditions.                                                                                                                             |

Before production claims, commission an independent threat model and security assessment, test the actual target provider contract and infrastructure, and document findings, owners, remediation and retest. This project does not claim those reviews have occurred. See [runtime guidance](ENTERPRISE-RUNTIME.md), [API](API.md), and [multi-agent evidence](MULTI-AGENT-EVIDENCE.md) for concrete operational limits.
